# 导入样例文件

这里的文件**全部是虚构数据**（昵称、账号、手机号、微信号都不是真实的），可以放心提交和分享。它们模拟钉钉多维表导出的样子，用来试一遍导入向导，也用作自动化测试的样本。

重新生成：`pnpm samples:import`（内容由 `apps/server/src/import/sample-data.ts` 定义，改了那里再重新生成）。也可以在导入页点「下载样例文件」。

## 钉钉多维表导出示例.xlsx

5 张 sheet，故意放成"合作跟踪"在最前面，用来演示导入时会**按依赖顺序**处理（商品 → 达人 → 联系人 → 合作 → 寄样）：合作表引用的达人和商品，来自同一个文件里的另外两张表。

| Sheet | 目标 | 表里的各种写法 | 预期结果 |
| --- | --- | --- | --- |
| 达人库 | 达人 | 第 1 行是合并的标题行，第 2 行空行，第 3 行才是表头；平台写成"红书""XHS""小红书/抖音"；粉丝数 `12.3w`、`1.2万`、`8,000`、`56789`；佣金 `20个点`、`25%`、`0.18`；报价 `¥1,500`、`1.2万`、`3k`；身份"达人""博主+买手" | 新增 5、更新 1（同一账号第二次出现）、疑似重复 1（`林小满.` 和 `林小满` 昵称几乎一样，要你裁决）、错误 1（没有昵称）；`很多`、`面议` 这类无法识别的值原样存进"导入原始值"并标黄 |
| 商品库 | 商品 | 标题行；价格 `¥1,999.00`、`1199元`、`1.1k`、`0.09万`；状态"上架""在架"；同一款号多行 = 多个规格 | A001 合并成 1 个商品 + 3 个规格；"面议"存为原始值 |
| 联系人 | 联系人 | 类型"经纪""机构"；手机是数字单元格或带空格；"关联达人"用 `/` 分隔多个 | 手机相同的行合并到已有联系人；缺类型的行报错；关联达人自动建立 |
| 合作跟踪 | 合作 | **两行表头**（上一行是合并的分组"基本信息/进度/合作条件"）；"达人"列是合并单元格（一场合作两个商品）；阶段写成"沟通中""在聊""已定档"；日期 `2026/10/21`、`10月25日`（缺年份会提示）、Excel 序列号 | 同一场合作的多个商品各自带佣金；阶段"火星"无法识别，必须先在枚举映射里处理；"洽谈中"没有下次跟进日期、找不到达人的行报错 |
| 寄样记录 | 寄样 | 状态"已发货""待发货"；同一快递单号的多行 = 一个包裹 | 一个包裹一张寄样单、多条明细；数量写成"两件"的行报错；没有快递单号的行有警告 |

## 达人库-GBK编码.csv

同一份达人数据，保存成 Excel"另存为 CSV"得到的 **GBK 编码**文件（没有标题行），用来验证 CSV 编码自动识别：用 UTF-8 打开会是乱码，导入时系统会识别为 GBK 并正确显示中文。

## 怎么试

1. 启动：`pnpm dev`，打开 http://127.0.0.1:5173/import
2. 上传 `钉钉多维表导出示例.xlsx`，一路"下一步"：系统会自动识别表头行、猜目标和列映射。
3. 在枚举映射里把合作表的"火星"映射成一个阶段（比如"暂缓"）；在查重裁决里决定 `林小满.` 是合并、跳过还是新建。
4. 预演页可以看到每一行是新增、更新、疑似重复，还是有警告或错误，并导出错误行。
5. 提交后在"导入批次"里可以**整批回滚**；勾选"保存为模板"后，再上传同样格式的表会自动套用，不用重新映射。
