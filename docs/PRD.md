# 达人直播工作台 PRD

> 版本：2026-10-18 · 来源：在线 PRD 文档导出（Claude Docs）。在线版为准，本文件供开发参考。

## 1. 背景与目标

达人直播工作台是品牌方自用的一体化平台，把商品、达人、合作、跟进和寄样回收放进同一套数据，并用 AI 把聊天记录和截图变成经人工确认的结构化改动。

**现状**：目前用钉钉多维表管理。问题在于没有一个能统一所有数据的工作平台，部分功能缺失或用起来不顺手。

**主要痛点**

- 跟进靠记忆，到期该联系谁没有提醒入口，容易漏跟。
- 样衣寄出后，达人漏寄回、寄回有污渍或破损、缺配件等问题难追踪、难追责。
- 达人、MCN、经纪人、私人商务的关系分散，同一个联系人管多个达人时信息重复。
- 报价和合作条件散落在微信聊天里，录入表格费时，容易出错。

**产品定位与差异化**：不和多维表比拼通用表格能力，只做它做不好的三件事。

1. AI 把一句话或截图变成"待确认的改动"，人工确认后才入库，保留原文出处，可撤销、可追溯。
2. 品牌方专属工作流开箱即用：今日跟进、寄样与回收质检、合作阶段看板。
3. 商品、达人、联系人、合作四类数据互相关联，一处更新，处处可查。

**V1 成功指标**

| 指标 | 目标 |
| --- | --- |
| 切换日后钉钉多维表新增录入 | 4 周内为 0 |
| 打开"今日跟进"的天数 | 每周 ≥ 5 天 |
| 到期跟进当周完成率 | ≥ 80% |
| AI 提取被直接确认（未修改）的比例 | ≥ 80% |
| 确认后被发现录错的金额或佣金 | 0 |
| 一条跟进从粘贴到入库的耗时中位数 | ≤ 15 秒 |
| 重复达人档案占比 | < 2% |
| 寄样记录缺回收状态的占比 | < 5% |

## 2. 用户与使用场景

V1 的用户是品牌方负责达人合作的一个人，在本机浏览器里使用。以后可能部署到局域网，供多名商务共用。

**业务前提**

- 主营服装类商品，样品以样衣为主，按款、色、码记数量，没有逐件编号。
- 平台以小红书为主，抖音、视频号次之。
- 合作都是线下约定，V1 以纯佣为主。坑位费加佣金、专场作为选项保留。
- 对接对象包括达人本人、MCN、经纪人和私人商务。

**典型一天**

1. **上午**：打开首页，看今日待跟进的人、逾期未寄回的样衣、近期待开播的合作。首页摘要在打开时生成，当天缓存。
2. **白天**：和达人或经纪人在微信上沟通后，把聊天文字或截图粘贴进工作台。AI 生成改动卡片，比如更新合作阶段、佣金、下次跟进日期，确认后入库。
3. **寄样**：确认合作后登记寄样，选择款、色、码和数量，填写快递单号和应寄回日期。
4. **收到回寄**：按款、色、码核对数量，记录质检结果，有问题的标记处理方式。
5. **其他**：随时在聊天框里提问，比如"哪些达人签收两周还没开播"。

**切换日**：数据导入完成后，约定一个切换日，之后只在工作台录入，钉钉多维表停止新增。工作台提供导出功能作为退路，不做与钉钉的双向同步。

## 3. 版本范围

V1 聚焦"数据统一 + 跟进 + 寄样回收 + AI 录入"，复盘、排期和协作放到后续版本。

| 版本 | 范围 |
| --- | --- |
| V1 | 商品库；达人库（多平台账号）；联系人/机构库；合作跟踪（看板+列表）；跟进记录与今日跟进；寄样与回收质检；自定义格式 Excel 导入导出；AI 一句话/截图录入；查重合并；审核队列与变更日志；外发设置与日志；自动备份 |
| V2 | 直播排期日历；复盘与 ROI（GMV、退货、佣金、样品成本）；坑位费付款与开票；专场商品清单；建联话术与商品简报生成；复盘问答 |
| V3 | 局域网多人部署、登录与权限、按负责人分配；基于历史数据的达人推荐；可选的提醒推送 |

**明确不做**

- 爬取或抓取任何平台数据，使用他人 Cookie，购买联系方式库
- 对接平台开放接口拉取达人数据
- 代发私信或自动建联
- 与钉钉多维表双向同步
- 移动端 App
- 财务结算和打款

## 4. 核心概念与数据模型

合作是核心实体：它连接一个达人账号和一到多个商品，跟进记录挂在合作下面，样品则按达人记账。

**实体关系（原文档中为关系图）**

```
联系人/机构 ──多对多── 达人 ──1对多── 平台账号（唯一键：平台+账号ID）
                        │
                        ├─1对多── 合作 ──1对多── 跟进记录（也可挂达人或联系人）
                        │          └─1对多── 合作商品 ──多对1── 商品 ──1对多── 商品规格（颜色×尺码、尺码表）
                        │
                        └─1对多── 寄样单 / 退样单（按日期记录，可关联合作）
                                     └─ 明细（款号、款名、颜色、尺码、数量、质检）── 按款色码对应 ── 商品规格
```

每个合作指定一个达人账号，可包含多个商品；跟进记录挂在合作下；寄样单和退样单挂在达人下（可关联合作），明细按款、色、码对应到商品规格。

**公共字段**：所有表都有 ID（ULID）、创建时间、更新时间、创建人、负责人、版本号（乐观锁）和软删除时间。单人模式下，创建人和负责人自动填为默认用户。

### 4.1 商品

| 字段 | 说明 |
| --- | --- |
| 款号、名称 | 必填：款号、名称 |
| 规格（颜色 × 尺码） | 子表，每行一个色码组合 |
| 平台商品 ID / 链接 | 子表，按平台分别记录 |
| 日常价、直播价、到手价、双十一价、六一八价、机制赠品 | 一套价格，不按平台区分；双十一价、六一八价可选 |
| 尺码信息 | 尺码表：每个尺码的衣长、胸围、肩宽等，可附尺码图 |
| 产品图片 | 可上传多张，第一张为主图 |
| 卖点 | 填写产品的卖点，可以 AI 生成 |
| 状态 | 在售 / 下架 |

### 4.2 达人与平台账号

一个达人下挂多个平台账号。查重以"平台 + 账号 ID"为唯一键。

| 达人字段 | 说明 |
| --- | --- |
| 昵称、真实姓名 | 真实姓名为个人信息，可选 |
| 类目标签、风格标签 | 多选 |
| 合作方式偏好、参考佣金/报价 | 带更新时间与来源 |
| 评级、黑名单原因 | 评级参考回收问题次数 |
| 收货地址 | 可以有多个；个人信息 |
| 关联联系人 | 多个，标出主要对接人 |

| 平台账号字段 | 说明 |
| --- | --- |
| 平台 | 小红书 / 抖音 / 视频号 |
| 账号 ID、主页链接 | 账号 ID 必填 |
| 身份 | 博主 / 买手 / 两者 |
| 粉丝数、场均观看、场均销售额区间 | 带数据日期，超过 90 天标灰 |

### 4.3 联系人 / 机构

MCN、经纪人、私人商务单独建表。一个联系人可以管多个达人，换联系方式只改一处，跟进也可以挂在联系人上。

| 字段 | 说明 |
| --- | --- |
| 姓名、类型 | 类型：达人本人 / MCN / 经纪人 / 私人商务 |
| 所属机构 | 可选 |
| 微信、手机 | 个人信息，本地保存，外发脱敏 |
| 关联达人 | 多对多 |

### 4.4 合作

| 字段 | 说明 |
| --- | --- |
| 达人、平台账号、对接联系人 | 必填：达人和平台账号 |
| 合作模式 | 纯佣（默认）/ 坑位费+佣金 / 专场 |
| 阶段 | 见 5.3 |
| 付款状态 | 独立于阶段；V1 仅坑位费模式使用 |
| 坑位费 | 预留，以"分"为单位存整数 |
| 开播日期 / 时段、挂链方式 | 可选 |
| 下次跟进日期 | 由最新跟进记录自动刷新；洽谈中另有跟进状态和跟进次数，见 5.3 |
| 流失原因 | 阶段为流失或放弃时必填 |
| 合作通道、报备状态 | 可选，因合作都在线下约定 |

**合作商品**：合作和商品的关联表，每行记录本次合作的佣金率、直播价和机制。同一场合作里的不同商品可以设不同佣金。

### 4.5 跟进记录

| 字段 | 说明 |
| --- | --- |
| 时间、方式 | 方式：微信 / 电话 / 平台消息 / 其他 |
| 关联对象 | 合作、达人或联系人，至少一个 |
| 内容摘要、意向 | 意向：高 / 中 / 低 |
| 跟进状态、下一步动作、下次跟进日期 | 保存后同步到合作 |
| 出处 | AI 录入时附原文或截图 |

### 4.6 样品台账（以达人为单位）

样品以达人为单位记账：每个达人一本样品台账，汇总他所有的寄出和退回，不受合作先后或交叉的影响。寄出和退回都按款、色、码记数量。

台账由两类按日期记录的单据组成：寄样单（寄出）和退样单（退回）；"还有哪些未寄回"由系统根据两者自动计算。

| 寄样单字段 | 说明 |
| --- | --- |
| 达人、收件人、收货地址 | 必填：达人。状态：待寄样 → 已寄出 → 已签收 |
| 关联合作 | 可选，用于知道这批样衣是为哪一场寄的 |
| 寄出日期、快递公司、单号、签收日期 | |
| 应寄回日期 | 默认开播日 + N 天；未排期时按签收日 + M 天；可手动修改 |
| 明细 | 子表：款号、款名、颜色、尺码、数量、单件价值 |

| 退样单字段 | 说明 |
| --- | --- |
| 达人、退回日期、快递公司、单号 | 一个包裹一张退样单，可包含多场合作的样衣 |
| 明细 | 子表：款号、款名、颜色、尺码、退回数量、质检结果、照片、处理结果 |
| 质检结果 | 完好 / 污渍 / 破损 / 缺配件 / 吊牌缺失 / 其他 |
| 处理结果 | 重新入库 / 报损 / 待沟通 / 索赔 |

退回时不需要指定来自哪张寄样单：系统按款、色、码，从该达人最早未结清的寄出记录开始冲抵，也可以手动指定。

**在外结余**由系统计算，不手工录入：

| 字段 | 说明 |
| --- | --- |
| 款号、款名、颜色、尺码 | |
| 累计寄出、累计退回、已核销、在外数量 | 在外 = 寄出 − 退回 − 核销 |
| 最早应寄回日期、是否逾期 | |
| 核销原因 | 报损、达人买断、赠送等不再追回的情况 |

### 4.7 自定义字段

商品、达人、联系人、合作四类实体都支持用户自己加字段。字段定义存在单独的表里（名称、类型、选项、是否敏感、是否允许外发），值存在实体的 JSON 列里，常用于筛选的字段建索引。导入时新建的列也走这里。

## 5. 功能需求（V1）

V1 共 8 个功能模块，每个模块附验收标准。

### 5.1 首页

- 今日待跟进：下次跟进日期 ≤ 今天的合作和联系人，按逾期天数排序，可一键"记一笔跟进"。
- 寄样预警：逾期未寄回、已签收超过 N 天未开播（N 可配置，默认 14）、寄回有质检问题待处理、待寄样超过 3 天未寄出。
- 近 7 天待开播的合作，以及其中挂链或佣金未确认的。
- 待审核改动数量，点击进入审核队列。
- AI 摘要：打开页面时生成，同一天缓存，可手动重新生成。

**验收**：首页在 1 秒内显示列表数据，摘要异步加载，不阻塞页面。

### 5.2 商品库、达人库、联系人库

- 列表视图：筛选、排序、列显隐、保存视图，自定义字段可作为列。
- 详情抽屉：基本信息、平台账号、关联联系人、合作历史、跟进时间线、寄样记录、变更历史。
- 达人详情自动汇总：合作次数、寄样次数、回收问题次数。
- 新建达人时按"平台 + 账号 ID"实时查重；昵称相似时提示"疑似重复"，可选择合并。

**验收**：重复账号 ID 无法新建第二条；合并后跟进、合作、寄样记录全部归到保留的档案下。

### 5.3 合作跟踪

看板按阶段分列，拖动卡片改变阶段；同时提供列表视图。主线阶段如下：

1. 待建联
2. 洽谈中（可多轮跟进，见下方"洽谈中的跟进状态"）
3. 已确认（佣金、机制谈定）
4. 待寄样（已确定要寄的款，样衣还没寄出）
5. 已排期（样衣已寄出，等待开播；开播日未定时卡片标"档期待定"）
6. 已开播
7. 待退样（已开播，还有样衣在达人手上）
8. 待复盘
9. 完成

旁支状态为暂缓、流失、放弃，可从任一阶段进入。付款状态（未付 / 已付 / 已退）是独立字段，只在坑位费模式下显示。

**洽谈中的跟进状态**：洽谈通常要来回多次。合作停在"洽谈中"时，另有一个跟进状态记录谈到了哪一步，每记一笔跟进都会更新它。

| 跟进状态 | 含义 |
| --- | --- |
| 已发邀约 | 首次联系，等待对方回复 |
| 待回复 | 已沟通，对方还没答复 |
| 报价中 | 对方已回复，正在谈佣金或机制 |
| 选款中 | 对方在挑款，确定要寄哪些样衣 |
| 等档期 | 条件基本谈妥，等对方给开播时间 |
| 暂无意向 | 对方暂时不考虑，约定以后再联系 |

- 洽谈中的合作必须有下次跟进日期；保存跟进记录时没填，会提示补上，避免跟一次就断掉。
- 卡片显示跟进次数、当前跟进状态和距上次跟进的天数，例如"第 3 次跟进 · 报价中 · 4 天前"。
- 连续 3 次（可配置）跟进状态都是"待回复"时，提醒是否转为暂缓或流失。
- 跟进状态的选项可以在设置里增删。

**验收**：阶段变化写入变更日志；进入流失或放弃必须填写原因；新建待寄样单后进入"待寄样"，寄出后进入"已排期"，开播日过后进入"已开播"，开播后仍有在外样品时进入"待退样"，样品结清后进入"待复盘"；自动推进都可以手动改回。

### 5.4 跟进记录

- 可挂在合作、达人或联系人上，在各自详情页以时间线显示。
- 保存时，若填写了下次跟进日期，自动刷新关联合作的同名字段。
- 支持表单录入和 AI 录入两种方式。

**验收**：一条跟进从粘贴文字到确认入库，中位耗时 ≤ 15 秒。

### 5.5 达人样品台账

1. **达人样品页**：达人详情里新增"样品"标签页，分三块。
    - 在外结余：按款号、款名、颜色、尺码列出还没退回的数量和应寄回日期，逾期标红。
    - 流水时间线：按日期倒序列出每次寄出和退回，例如"10月12日 寄出 A001 羊毛大衣 黑色 M ×1、S ×1""10月20日 退回 A001 羊毛大衣 黑色 M ×1（完好）"。
    - 累计汇总：累计寄出、累计退回、在外件数、逾期件数、质检问题次数。
2. **新建待寄样**：合作确认后，选择达人（可关联合作）和要寄的款、色、码、数量，生成待寄样单。此时还没发货，只记下"要给谁寄什么"。
3. **寄出**：发货后在待寄样单上填写收货地址、快递信息、寄出日期和应寄回日期，状态变为"已寄出"，样衣计入在外。
4. **登记退回**：选择达人后，系统列出他所有在外样品；勾选这次收到的款、色、码和数量，逐项质检，可上传照片。一个包裹里有多场合作的样衣，也一次登记完。
5. **处理问题**：质检不合格的明细选择处理结果；确定不再追回的在外样品做核销，并填写原因。
6. **交叉合作**：上一场的样衣留给下一场用时，不退回也不重新寄出，只需把相关在外样品的应寄回日期延后，并记一条说明。
7. **寄样页筛选**：
    - 待寄样：按达人列出要寄哪些款、色、码和数量，可以批量标记寄出。
    - 在外、有逾期、质检待处理、已结清。
    - 首页寄样预警同样按达人汇总，并提示待寄样超过 3 天还没寄出的。
8. **结清**：达人在外数量归零后，可以选择清除他的收货地址。

**验收**：任一达人的在外数量 = 累计寄出 − 累计退回 − 核销，按款、色、码自动计算；一个包裹含多场合作样衣时能一次登记；每出现一次质检问题或缺件，达人的"回收问题次数"加 1。

### 5.6 审核队列与变更日志

- 敏感操作只生成待审核改动，需人工确认后执行。敏感操作包括：删除、合并达人、批量修改、修改金额或佣金、修改已完成的合作。
- 审核卡片显示改动前后的对比，可逐条或整批通过、驳回。
- 待审核改动不会过期。审核时如果记录已被修改，判为冲突，需重新确认。
- 每次写入记录改动前后的值、操作者（用户 / AI / 导入）和批次号，可按条或按批撤销。

用户在页面上手动修改合作阶段、下次跟进日期等普通字段时直接生效，不进审核队列，但同样记入变更日志、可撤销。AI 提出的修改一律需要审核。

**验收**：AI 和导入产生的任何敏感改动，未经确认都不会写入数据库。

### 5.7 导入导出、外发设置、AI 助手

分别见第 6、7、8 节。

### 5.8 备份

- 每天自动把数据库复制一份到用户指定的目录，保留最近 30 份。
- 提供手动备份和从备份恢复。

**验收**：删除数据库文件后，能从最近一份备份完整恢复。

## 6. 自定义 Excel 导入导出

导入不预设固定模板：每个表格的列由用户映射到系统字段，映射关系可以保存成模板，下次自动套用。

### 6.1 导入流程

1. **上传**：支持 .xlsx、.xls、.csv；CSV 自动识别 GBK 和 UTF-8 编码。
2. **选择 sheet 与目标**：勾选要导入的 sheet，每个 sheet 选择目标实体（商品 / 达人 / 联系人 / 合作 / 寄样）。
3. **识别表头**：自动推荐表头所在行，支持表头不在第一行、多行表头、合并单元格；用户可以手动改。
4. **列映射**：左侧为源列和 5 行样本，右侧为目标字段下拉。可以选择"新建自定义字段""存为原始值"或"忽略"。
5. **值转换**：为每列选择转换规则，见 6.2。
6. **枚举映射**：把源表中的选项值映射到系统选项，比如"沟通中""在聊"都映射到"洽谈中"。未知值必须处理后才能继续。
7. **预演校验**：逐行标出新增、更新、疑似重复、警告、错误，不写入数据库；错误行可以导出。
8. **查重裁决**：对疑似重复的记录选择合并、跳过或新建；合并时按字段选择保留旧值、覆盖或仅填空值。
9. **提交**：作为一个导入批次写入，记录统计结果，可以整批回滚。
10. **保存模板**：保存映射、转换规则和枚举字典。

### 6.2 值转换规则

| 类型 | 能识别的写法 |
| --- | --- |
| 日期 | Excel 日期序列号、2026/3/1、2026-03-01、3月1日（缺年份时提示） |
| 金额 | ¥ 符号、千分位逗号、"1.2万""3k"；统一存为"分" |
| 粉丝数 | "12.3w""1.2万""3k""1,234"；统一存为整数 |
| 百分比 | "20%""20个点""0.2"；统一存为百分比数值 |
| 平台 | "红书""XHS""小红书"等写法归一 |
| 多值单元格 | 按分隔符拆分，如"小红书/抖音" |
| 无法解析 | 原样存入"原始值"，标黄提示，不丢数据 |

### 6.3 模板复用

系统按表头特征识别相似表格，自动套用最匹配的模板，并提示新增或缺失的列。模板可以在设置页查看、修改和删除。

### 6.4 AI 的角色

AI 只负责建议列映射和枚举映射，并给出置信度，最终由用户确认。发给模型的只有表头、每列最多 5 行脱敏后的样本，以及目标字段说明。关闭外发时，改用规则和同义词词典匹配。

### 6.5 回滚

每个导入批次的每一行改动都写入变更日志。回滚时逆序撤销；如果某条记录在导入后又被修改过，标为冲突，由用户逐条决定。

### 6.6 导出

- 任一列表视图可以导出为 .xlsx，包含自定义字段。
- 提供"全量导出"，每类实体一个 sheet，作为离开工作台的退路。

**验收**：同一份表格第二次导入时自动套用模板，用户无需重新映射；导入任意一批后能完整回滚。

## 7. AI 助手

AI 只提出改动，不直接改敏感数据：低风险的新增可以直接写入并撤销，其余改动一律进入审核队列。

### 7.1 V1 能力

1. **一句话录入**：例如"刚和小美的经纪人聊了，佣金 25%，下周三播，样衣明天寄 S、M 各一件"，生成跟进记录、合作字段更新和寄样草稿。
2. **截图录入**：识别微信聊天截图、达人主页截图，提取达人信息、佣金、日期。截图先在本地 OCR，按外发规则决定发送哪些文字。
3. **问答**：基于工具查询结果回答，例如"签收超过两周还没开播的有哪些""某 MCN 手上有哪些达人"。回答附记录链接；查不到就说查不到。
4. **首页摘要**：打开首页时生成当日概况。
5. **导入映射建议**：见 6.4。

### 7.2 领域工具

Agent 只能调用下列工具，不开放 SQL、命令行和文件读写。

| 类别 | 工具 | 执行方式 |
| --- | --- | --- |
| 只读 | 搜索/查看商品、达人、联系人、合作、跟进、寄样；参数化统计查询 | 直接执行，返回结果先按外发规则脱敏 |
| 低风险写 | 新增跟进记录；新建草稿合作；新建寄样草稿 | 直接执行，生成可撤销卡片 |
| 敏感写 | 修改字段；修改金额或佣金；改变阶段；合并达人；删除；批量修改 | 只生成待审核改动 |
| 辅助 | 获取当前时间（Asia/Shanghai）；建议导入映射 | 直接执行 |

### 7.3 护栏

- **目标确认**：AI 给出目标达人或合作的候选，名字匹配到多个时不允许自动选择；一次提取只写一个合作。
- **金额与佣金**：必须带类型和单位，"w""k""个点"统一换算；数值和原文逐字核对，对不上拒绝写入。佣金超过 50%、或明显偏离该达人历史值时，卡片标黄警告。
- **日期**："下周三""月底"等相对日期由程序解析，不让模型计算；卡片上回显为"10月21日 周三"这样的绝对日期。
- **出处**：每条 AI 改动保留原文或截图，在详情页可以查看。
- **数量上限**：单次批量改动不超过 200 条。

**验收**：确认后的金额、佣金字段错误为 0；AI 改动被直接确认（未修改）的比例 ≥ 80%。

## 8. 隐私、外发与安全

所有数据存在本机；发给模型的内容一律先脱敏，发什么、发给谁都可以配置，并留有日志。

### 8.1 个人信息

达人和联系人的微信、手机号、真实姓名、收货地址属于个人信息，适用《个人信息保护法》。处理依据为合作所需（订立和履行合同），遵循最小必要原则：

- 这些字段标记为"敏感"，列表默认打码显示，点击后查看。
- 达人样品全部结清后可以清除收货地址。
- 删除达人时，一并删除其联系方式和地址。

### 8.2 外发配置

| 层级 | 可配置项 |
| --- | --- |
| 全局 | 是否允许外发；仅允许境内模型；仅允许本地模型 |
| 按模块 | 商品、达人、联系人、合作、跟进、寄样分别允许或禁止 |
| 按字段 | 每个字段（含自定义字段）允许、禁止或脱敏后发送 |

**固定规则**：手机号、微信号、地址、真实姓名无论如何配置，外发前都会被本地脱敏，无法关闭。

**外发日志**：记录每次请求的时间、模型、模块和实际发出的内容（脱敏后），可在设置页查看和导出。

### 8.3 安全

- 服务只监听 127.0.0.1，V1 不需要登录。
- 模型 API Key 存在本地配置文件或系统钥匙串，不进数据库，不返回给前端。
- 前端只调用本地后端，不直接请求模型。

**验收**：在外发日志中，任何一条记录都不含未脱敏的手机号、微信号或地址。

## 9. 技术方案

单进程 Node 服务：Web 前端调用本地后端，后端在同一进程内运行 Pi agent，agent 与 REST 接口共用同一层领域服务，数据存在 SQLite。

**系统架构（原文档中为架构图）**

```
浏览器前端（React）：首页 · 合作看板 · 达人/商品/寄样 · 导入向导 · 审核 · AI 侧栏
        │ REST                         │ SSE 流式聊天
        ▼                              ▼
┌──────────────── Node 后端（单进程，仅监听 127.0.0.1）────────────────┐
│  REST 接口                 Pi Agent 会话 ──────────► 外发过滤       │
│  （页面增删改查、导入导出）  （内置工具关闭，只用领域工具） （按规则脱敏，记外发日志）│
│        │                        │ 领域工具                 │       │
│        ▼                        ▼                          │       │
│  ┌──────────── 领域服务层 ────────────┐                    │       │
│  │ 校验 · 敏感改动进审核队列 · 变更日志与撤销 │                    │       │
│  └────────────────────────────────────┘                    │       │
└────────┬──────────────────────┬─────────────────────────────┼───────┘
         ▼                      ▼                             ▼ 脱敏后发送
   SQLite（WAL）           本地文件目录                    模型供应商
 业务数据、日志、待审核   截图、质检照片、会话、备份     国内、国外或本地 Ollama
```

页面操作和 AI 工具走同一层领域服务，校验、审核和变更日志只实现一次；Agent 的模型请求全部经过外发过滤。

### 9.1 技术选型

| 层 | 选型 | 说明 |
| --- | --- | --- |
| 前端 | React + Vite、TanStack Router/Query/Table、shadcn/ui、dnd-kit | 表格视图、看板拖拽、导入向导 |
| 后端 | Node.js ≥ 22.19、Hono 或 Fastify | REST + SSE 流式聊天 |
| Agent | @earendil-works/pi-coding-agent SDK | 关闭内置工具，只注入领域工具 |
| 数据库 | SQLite（WAL 模式）+ Drizzle ORM | 以后可迁移到 Postgres |
| 表格解析 | SheetJS、papaparse、iconv-lite | 合并单元格、多 sheet、GBK |
| OCR | 本地 OCR 引擎（待选型） | 截图先在本地识别 |

### 9.2 Agent 接入

- 用 SDK 的 createAgentSession() 创建会话，设置 noTools 为 "builtin"，关闭 bash 和文件读写等内置工具。
- 领域工具通过 customTools 传入，参数用 TypeBox 定义；工具内部调用领域服务，服务层再次校验参数和权限。
- 用扩展的 tool_call 事件做兜底拦截（白名单、限流）。
- session.subscribe() 监听文本增量和工具执行事件，转成 SSE 推给前端；停止按钮调用 session.abort()。
- 会话按 Pi 的 JSONL 树保存，数据库只存会话索引。
- 锁定 Pi 版本，并在 SDK 外包一层适配，隔离上游 API 变动。

### 9.3 多模型

- 模型由设置页配置，V1 默认留空。支持 Anthropic、OpenAI，以及 OpenAI 兼容接口的国内模型（DeepSeek、通义、Kimi 等）和本地 Ollama。
- 用 Pi 的 ModelRuntime 指向工作台自己的 models.json。
- 可以给不同用途指定不同模型，例如录入提取用一个、摘要用另一个。

### 9.4 为多人部署预留

- 现在就建用户表；所有记录带创建人和负责人，所有写入带操作者。
- 所有表带版本号，更新时校验，避免多人同时编辑互相覆盖。
- 认证在 V3 加入：账号密码 + HttpOnly Cookie，权限分管理员和成员两档。
- Agent 会话按用户分目录保存。
- SQLite WAL 足够支撑 10 人以内的局域网使用；需要更高并发时，通过 Drizzle 迁移到 Postgres。

### 9.5 运行方式

- 一条命令启动，浏览器打开 localhost。
- 数据目录：数据库、附件（截图、质检照片）、Pi 会话、备份，整体可拷贝迁移。

## 10. 页面与信息架构

V1 共 9 个页面，加一个在每个页面都能呼出的 AI 侧栏；侧栏知道当前页面和选中的记录。

| 页面 | 主要内容 |
| --- | --- |
| 首页 | AI 摘要、今日跟进、寄样预警、近 7 天开播、待审核数量；常驻"粘贴文字/截图"输入框 |
| 合作 | 看板（按阶段）与列表两种视图；合作详情抽屉 |
| 达人 | 列表、筛选、保存视图；达人详情抽屉（账号、联系人、合作、跟进、样品台账、变更历史） |
| 联系人 | MCN、经纪人、私人商务列表；详情显示管辖的达人和沟通记录 |
| 商品 | 列表；详情含图片、色码规格、尺码表、合作记录 |
| 寄样 | 筛选待寄样、在外、逾期、质检待处理；按达人汇总；登记寄出、退回与质检 |
| 审核 | 待审核改动，前后对比，逐条或整批处理 |
| 导入 | 导入向导、导入批次记录（含回滚）、映射模板管理 |
| 设置 | 模型配置、外发规则与日志、自定义字段、枚举选项、备份、变更日志 |

**录入入口**：每个列表都可以用表单新建；首页输入框和 AI 侧栏可以粘贴文字或截图。AI 生成的改动以卡片形式出现在侧栏，卡片上可以直接修改字段后再确认。

## 11. 风险、待核实事项与开放问题

最大的风险是做完不用，所以 V1 以"切换日后 4 周不再录入多维表"为第一检验标准。

### 11.1 风险与应对

| 风险 | 应对 |
| --- | --- |
| 和多维表比没有明显优势，被弃用 | 只做差异化能力；按成功指标评估，不达标先改进再加功能 |
| 数据两边录，两边都不准 | 设切换日，不做双向同步，提供全量导出作为退路 |
| 录入比多维表慢 | 粘贴文字或截图为主入口，15 秒内完成一条跟进 |
| 达人数据过时 | 字段带更新时间，超过 90 天标灰 |
| AI 识别错金额或写错对象 | 7.3 中的护栏；敏感改动必须审核 |
| Pi SDK 接口变动快 | 锁定版本，加一层适配 |
| 国内模型工具调用不稳定 | 开发时建立工具调用回归测试，换模型前先跑一遍 |
| 单机数据丢失 | 每日自动备份，保留 30 份 |

### 11.2 待核实事项

- Pi SDK：自定义工具的导出名、SDK 模式下 tool_call 拦截是否生效。开发第一步验证。
- 本地 OCR 引擎的选型，以及对微信截图的识别准确率。
- 小红书寄样或付费合作的报备规则与门槛。本产品合作都在线下约定，暂不影响 V1，仅作合规提醒。
- SheetJS 最新版本需从官方 CDN 安装，具体版本号开发时确认。
